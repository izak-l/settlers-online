# 017 — Variable setup for seafaring scenarios

## Goal

Each of scenarios 1–4 can be played on a random board, as the rulebook's "variable setup" describes, chosen in the lobby as Fixed or Variable. Part of M10 (M10d), after spec 015.

## Scope / non-scope

**Scope**

- Named pools: a map can have several terrain and number-disc pools, each drawn only into its own hexes (e.g. the main island's pool and the small islands' pool).
- New placement rules for the generator, scoped to a pool or the whole map.
- Variable maps (3p and 4p) for scenarios 1–4.

**Non-scope**

- Variable setup for scenarios 5–8 (the rulebook gives a few small variations; decided in their own specs) and the new world (spec 022 has its own generator).

## Rules (rulebook pages 5, 7, 9, 11)

- Scenario 1: main island hexes, discs and ports random in the main island area; the remaining land and discs random in the small island areas; no 6 or 8 next to each other; the robber starts on the 12 (3p) or the desert (4p).
- Scenario 2: land and discs random over the four island areas; forests and pastures never get 2, 3, 11 or 12; ports may be shuffled over the fixed port spots; the robber starts on the 12.
- Scenario 3: face-up land and discs random in the two island areas; 6s and 8s may be next to each other; port spots fixed, port types shuffled; the robber starts on the 12.
- Scenario 4: deserts fixed; main island land, discs and ports random in its area; the rest random in the remaining spaces; no adjacent 6/8; no 6 or 8 on gold.

## Engine changes

- None. The engine receives a resolved map, as today.

## Maps changes

- `pools` becomes named: `pools.terrain: Record<name, counts>`, `pools.tokens: Record<name, number[]>`, `pools.ports: Record<name, counts>`. A hex says `"terrain": "pool:<name>"`, `"token": "pool:<name>"`. Existing maps and drafts move to the new shape with a one-off script (`land` / `tokens` / `ports` keep those names), so nothing changes for them.
- Constraints gain a scope and three new rules: `no-adjacent-red-tokens` (as today), `no-red-on-gold`, `no-low-tokens-on: [forest, pasture]` (2, 3, 11, 12). Each may name the pools it applies to.
- `robberStart` accepts `"token:12"`.
- The validator counts every named pool against its hexes. The generator resolves pools one at a time with the game RNG, retrying a pool that breaks a constraint (as today, up to 1,000 times).

## Server/UI changes

- None beyond spec 015's lobby toggle; the server picks `<seats>-variable.json`.

## Test plan

- Generator: every variable map resolves over 1,000 seeds with its constraints holding; pools never mix; counts match the rulebook's component lists.
- Migration: every existing map generates the same board for the same seed before and after the pool change.
- `pnpm sim --scenario <n> --setup variable` runs clean for 1–4.

## Open questions

- None.

## Status

Shipped (M10d, on `m10`) for scenarios 1, 2 and 4; scenario 3's variable maps come with spec 016. As built: constraints are whole-map rules (no per-pool scope was needed); the variable maps are generated by `scenarios/build.ts` from the fixed layouts (each area's pool is exactly that area's terrain and tokens on the fixed map, and port types are shuffled over the fixed port spots); `robberStart: "token:N"` is resolved by the generator, so the engine is unchanged.
